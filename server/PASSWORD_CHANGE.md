# 공통 관리자 비밀번호 변경

연수 관리자와 메인 자료실은 같은 관리자 비밀번호 및 세션 저장소를 사용합니다. 연수 manage.html의 로그인 전 ‘관리자 비밀번호 변경’, 또는 로그인 후 ‘비밀번호 변경’에서 현재/새/확인을 입력합니다. 성공하면 양쪽의 기존 관리자 세션이 모두 무효화됩니다. 새 비밀번호로 다시 로그인해야 합니다. 신청, 선정, 조회용 PIN, 자료, 조회수, 다른 설정은 유지됩니다.

POST /api/admin/password
- 허용된 Origin 필수. JSON: currentPassword, newPassword, confirmPassword.
- 로그인 여부와 무관하게 실제 현재 비밀번호를 기존 PBKDF2 verifier로 확인합니다.
- X-Pic8-QA 헤더가 있으면 거부하며 QA verifier는 변경에 사용할 수 없습니다.
- 새 비밀번호: Unicode 코드 포인트 기준 4~1024자. 공백을 자르거나 정규화하지 않습니다. 확인 입력이 정확히 같아야 합니다.
- IP별 15분 6회, 전체 15분 60회 제한. 비밀번호/본문/인증 헤더를 로그에 남기지 않습니다.
- 응답은 passwordChanged/reauthenticationRequired boolean만 반환합니다. 비밀번호를 브라우저 저장소나 URL에 쓰지 않습니다.

저장 및 복구 경계
- 프로세스 내부 잠금 및 OS 파일 잠금으로 변경/로그인을 직렬화합니다.
- 임시 설정 파일을 비공개 권한으로 작성하고 fsync한 다음 초기 admin-password.txt 삭제가 성공해야 설정을 원자적으로 교체합니다. 새 평문 파일은 만들지 않습니다.
- 초기 파일 삭제나 교체 전 저장 실패 시 기존 인증 설정이 유지됩니다. 교체 실패 전에 초기 파일만 삭제될 수 있지만, 현재 암호 검증/세션은 그대로 유지됩니다. 초기 파일을 다시 만들지 않습니다.
- 원자 교체가 커밋 지점입니다. 새 임의 session epoch를 설정에 함께 저장하므로 세션 DB 정리 실패/커밋 직후 종료에도 기존 토큰은 재시작 후 사용할 수 없습니다. 다른 설정은 최신 설정에서 그대로 보존합니다.
- 기존 CLI set-password도 동일 저장 경로를 사용합니다. 실행 중 인증은 최신 설정을 읽으므로 재시작이 필요하지 않습니다.
- 응답이 끊겼다면 변경이 완료되었을 수도 있으므로 새 비밀번호 로그인을 확인합니다. 변경 요청을 자동 재전송하지 않습니다.

검증
- 운영 비밀번호 변경/복원 테스트 금지. 성공 회전은 별도 home/config/DB에서만 수행합니다.
- python -B -m unittest discover -s server -p 'test_*.py'
- 운영 배포 시 운영 config.json을 서버 메모리 안에서 전후 비교해 boolean만 보고합니다. 운영 admin-password.txt는 내용을 읽지 않습니다.
